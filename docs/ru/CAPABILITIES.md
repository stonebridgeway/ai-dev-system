# Профили возможностей

[← README](../../README.ru.md) · [Установка](INSTALL.md) · [Рабочий процесс](WORKFLOW.md) · [Ограничители](GUARDRAILS.md)

Агенту сервер отдаёт 135 инструментов. Это преимущество, когда агенту нужен один из них,
и плата всё остальное время: каждый инструмент в `tools/list` — это текст схемы,
который модель несёт в контексте ещё до того, как прочитала ваш запрос.

Профили возможностей режут эту поверхность по границам, в которых вы и так
мыслите.

## Восемь профилей

| Профиль | Инструментов | Что добавляет | Когда включать |
| --- | --- | --- | --- |
| **`core`** | 25 | Контекст проекта, маршрутизацию skills и задачу от первой команды до подтверждённого завершения. | Всегда. Его нельзя выключить. |
| `coding` | 18 | Эпики, plan gate, карточки проекта и auto-команды, инженерные правила репозитория. | Работа на несколько задач или репозиторий, чьи правила агент должен установить и соблюдать. |
| `memory` | 17 | Решения, передачи между сессиями, инстинкты, заметки за ними и галактика знаний, чтобы по ним летать. | Нужно, чтобы следующая сессия начиналась там, где закончилась эта. |
| `git` | 9 | Изолированные worktree, снапшоты и откат, разбор диффа, текст pull request. | Агент работает с настоящим рабочим деревом, которое вам дорого. |
| `frontend` | 13 | Бриф, визуальные направления, concept jury, дизайн-систему, фабрику референсов. | Разработка или ревью пользовательского интерфейса. |
| `qa` | 8 | Playwright и визуальный QA, а также бенчмарки, которые держат поиск и маршрутизацию честными. | Проверка должна давать доказательства, на которые можно посмотреть. |
| `security` | 9 | Сканы секретов и зависимостей, планы исправления зависимостей, политику команд и записи, хуки агента, инвентаризацию MCP. | Настройка ограничителей или аудит того, к чему подключены агенты. |
| `advanced` | 36 | Диаграммы Archify, индексы поиска и skills, дашборд, журнал расходов, упаковку runtime. | Обслуживание самой системы, а не работа в ней. |

Девятого профиля, `control`, в таблице нет, потому что агенту он не нужен: его
16 инструментов — состояние установки, настройка, локальная модель, подключённые
AI-клиенты, журналы, настройки, собственные скиллы человека и обзор работы — то, чем
управляет настольное приложение, и три из них удаляют (`model_remove`,
`clients_remove` и `custom_skills_remove`, все только с `confirm`). Пустой `AI_DEV_PROFILES` и `all` его не включают; сессия видит его,
только если назовёт: `AI_DEV_PROFILES=control` или `all,control` — чтобы получить всё.
Его ответы — контракт с версией:
[CONTROL-API.md](../../ai-dev-mcp-server/docs/CONTROL-API.md) *(на английском)*.

Каждый профиль работает на одном Node, с одним исключением во `frontend`:
`query_ui_ux_knowledge` и `generate_ui_ux_design_system` читают набор UI UX Pro Max
через его собственный скрипт на Python, поэтому им нужен Python 3 в `PATH` (или
`AI_DEV_PYTHON`). Без него они отвечают, что установить, а `npm run doctor`
помечает `ui_ux_knowledge` пропущенной.

Источник истины по каждому инструменту — колонка `Profile` в
[справочнике инструментов](../../ai-dev-mcp-server/docs/TOOLS.md), который
генерируется из определений самого сервера. Каждый инструмент принадлежит ровно
одному профилю, и CI не пропустит новый инструмент без профиля.

## Как включить

Задайте `AI_DEV_PROFILES` в окружении сервера — в блоке `env` вашего MCP-клиента
или в оболочке, которая его запускает:

```bash
AI_DEV_PROFILES=core,git        # 34 инструмента
AI_DEV_PROFILES="coding memory" # запятые или пробелы — работает и так, и так
AI_DEV_PROFILES=all             # все профили, что бы ни говорили настройки
```

`core` добавляется к тому, что вы назвали, поэтому `AI_DEV_PROFILES=git` и
`AI_DEV_PROFILES=core,git` — одно и то же.

**Если переменная не задана, включены все профили** — если только вы не выбрали
профили в настройках: значение `profiles` в `~/.ai-dev/config.json`, которое пишут
настольное приложение и инструмент `settings_set`, заполняет незаданную или пустую
`AI_DEV_PROFILES` для каждой команды `ai-dev`, а значит, для каждого клиента, которого
подключила локальная установка. Ничего не скрывается, пока вы об этом не попросите:
установка, которая никогда не слышала о профилях, ведёт себя ровно так же, как до их
появления.

В конфигурации клиента переменная ставится в блок `env` записи, рядом с теми, что в
записи уже есть (`AI_DEV_VAULT_ROOT`, `AI_DEV_HOME`):

```json
{
  "mcpServers": {
    "ai-dev": {
      "command": "/absolute/path/to/node",
      "args": ["/absolute/path/to/ai-dev-mcp-server/bin/ai-dev.mjs", "mcp"],
      "env": {
        "AI_DEV_PROFILES": "core,git,memory"
      }
    }
  }
}
```

Запись Docker запускает сервер в контейнере, куда её блок `env` не доходит: там
переменная ставится в аргументы `docker run`, `"--env", "AI_DEV_PROFILES=core,git,memory"`,
перед образом.

## Сколько это экономит

Замерено то, что клиент действительно получает: массив `tools` из ответа
`tools/list`, сериализованный, в байтах (1 КБ = 1000 байт):

| Значение | Инструментов в списке | Схема `tools/list` |
| --- | --- | --- |
| `core` | 25 | 23 574 байт (~24 КБ) |
| `core,git` | 34 | 33 600 байт (~34 КБ) |
| `core,coding,git,memory` | 69 | 70 428 байт (~70 КБ) |
| не задано / `all` | 135 | 140 645 байт (~141 КБ) |

Замерить самому (оболочка macOS / Linux; `AI_DEV_PROFILES` меняйте по строкам,
пустое — все инструменты):

```bash
cd ai-dev-mcp-server
printf '%s\n' \
  '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"size","version":"0"}}}' \
  '{"jsonrpc":"2.0","method":"notifications/initialized"}' \
  '{"jsonrpc":"2.0","id":2,"method":"tools/list"}' \
  | AI_DEV_PROFILES=core,git node src/server.mjs \
  | node -e 'let s="";process.stdin.on("data",(d)=>s+=d).on("end",()=>{for(const l of s.split("\n"))if(l.includes("\"id\":2")){const t=JSON.parse(l).result.tools;console.log(t.length+" tools, "+Buffer.byteLength(JSON.stringify(t))+" bytes")}})'
```

Числа — для сервера этого выпуска: новый или переформулированный инструмент их
меняет, поэтому команда здесь. Как клиент упакует схему в контекст модели —
решает клиент.

Чего сужение **не** делает:

- **Ничего не отключает.** Сужение затрагивает только `tools/list`. `tools/call`
  по-прежнему принимает любой инструмент по имени, так что клиент, который уже
  знает имя, продолжит работать, и ничто в системе не становится недоступным.
- **Это не граница безопасности.** Это управление бюджетом контекста.
  Отказывают в действии [ограничители](GUARDRAILS.md).

Суженный сервер сообщает об этом в stderr при запуске, называя профили и число
инструментов, чтобы «инструмент пропал» никогда не было необъяснимым симптомом:

```text
ai-dev: capability profiles core, git — 34 of 135 tools listed. Unset AI_DEV_PROFILES for all of them.
```

Нераспознанное имя профиля выводится в лог и игнорируется, а не превращает
список в пустой: опечатка не должна тихо стоить сессии половины инструментов.

## Что выбрать

- **Бэкенд или API:** `core,git` — и `coding`, когда работа выходит за одну задачу.
- **Долгий проект, к которому возвращаетесь:** `core,git,memory`.
- **Фронтенд:** `core,git,frontend,qa`.
- **Настройка репозитория для команды:** `core,coding,security`.
- **Разработка самого AI Dev System:** не задавайте переменную.

Если сомневаетесь — не задавайте. Профили нужны тогда, когда поверхность
инструментов начинает чего-то стоить, а не как обязательный шаг перед началом.
