# Переход с 2.x на 3.0

[← README](../../README.ru.md) · [Установка](INSTALL.md) · [Тест обновления](UPGRADE-TEST.md) · [История изменений](../../CHANGELOG.md)

3.0 — тот же сервер. Агент видит 135 инструментов — на два больше, чем в 2.0.0: `plan_security_fixes`
и `render_knowledge_galaxy`, — а приложение может включить ещё 16; хранилище и состояние задач
сохраняют свой формат, а индекс, построенный 2.x, читается без пересборки. Изменилось то, как AI Dev
ставится, как до него доходит клиент и где он держит несколько вещей. Установка 2.x продолжает
работать после обновления, кроме мест, где эта страница говорит иное: здесь сказано, что для неё
меняется, что переносится само при первом старте, что требует одной вашей команды и как вернуться.

`npm run upgrade:test` проверяет всё это на клоне 2.x, а `npm run docker:upgrade-check --
--old-image <образ 2.x> --new-image <образ>` — часть Docker на томе 2.x и его лаунчерах
([Тест обновления](UPGRADE-TEST.md)).

## Коротко

| У вас | Сделайте | Дальше |
| --- | --- | --- |
| Клон 2.x, настроенный `npm run setup` | `git pull`, затем `cd ai-dev-mcp-server && npm ci && npm run setup`; перезапустите всех ИИ-клиентов | Одна запись `ai-dev` на клиента, их обслуживает один демон; хранилище, задачи и индекс — как были |
| 2.x через Docker (`bootstrap.sh`, `bootstrap.ps1`, `run-mcp.sh`, `run-mcp.ps1`, `ClaudeMcpProxy.exe`) | `git pull`, затем снова `bootstrap.sh` (`bootstrap.ps1` на Windows) — он оставит папку проектов и папку модели, которые называют ваши записи 2.x; перезапустите всех ИИ-клиентов | Записи `docker run`; том сохранён, его навыки приведены к seed 3.0; на macOS и Linux удалён долгоживущий контейнер, который запускал `bootstrap.sh` 2.x (на Windows 2.x такого не держала) |
| Установка 2.x, которую пока не хочется трогать | Пока ничего | Она продолжает работать, а предупреждения ниже говорят, что запустить, когда будете готовы |
| 2.x на Mac | Пока останьтесь на 2.x: macOS в разработке, и 3.0 выходит только для Windows и Linux. Не делайте `git pull`; с Docker направьте лаунчеры 2.x на линию 2.x, `AI_DEV_IMAGE=ghcr.io/stonebridgeway/ai-dev-system:2`, — с релизом `:latest` станет 3.x ([Как вернуться](#как-вернуться)) | 2.x как есть, пока 3.0 не примут на Mac |

Новой машине ничего этого не нужно: поставьте 3.0 [любым из трёх способов](INSTALL.md#выбор-способа).

## Для всех

- **Меняется лицензия.** 3.0 выходит по [PolyForm Noncommercial License 1.0.0](../../LICENSE),
  © 2026 stonebridgeway: личное использование, учёба, исследования, хобби-проекты и некоммерческие
  организации — бесплатно, изменять код можно; коммерческое использование 3.0 — на работе, в продукте
  или сервисе компании — только по коммерческой лицензии от автора ([Telegram @stonebridgeway](https://t.me/stonebridgeway)). 2.x вышла под MIT и под ней
  остаётся: установка, которую не обновляют, сохраняет эти условия.
- **Имя сервера в клиенте — `ai-dev`.** 2.x писала `ai-dev-system` для локальной установки и `ai-dev`
  для Docker, и в клиенте могли быть обе. `setup` и `clients install` пишут одну запись `ai-dev`,
  удаляют `ai-dev-system` и говорят об этом; у каждого клиента один `ai-dev`, выигрывает установка,
  подключившая его последней. Запись 2.x работает до 4.0 (`clients list` помечает её `(2.x)`), а прежние
  байты каждого изменённого файла лежат рядом как `<файл>.backup-<время>`.
- **Node 22.16 или новее** (или 24+) для локальной установки; 2.x принимала 22.12. На более старом Node
  сервер запускается, а поисковые инструменты отвечают, какая версия им нужна. Docker на хосте Node не
  требует, кроме `bootstrap.ps1` на Windows (22.12+).
- **Без Python.** Поиск, его индекс и локальная модель работают в Node; поисковый помощник на Python
  удалён. Python остался двум инструментам UI UX Pro Max, и без него они говорят, что установить.
- **Dense-бэкенд на Python удалён.** На модель ONNX переводит одна команда: в клоне `npm
  run setup -- --model`, с npx — `npx ai-dev-system setup --model`. Она заново строит
  векторы документов; векторы Python — векторы другой модели, они хранятся, но не сравниваются, пока
  она их не заменит. `AI_DEV_DENSE_BACKEND=python` читается как `auto` с пометкой; `BGE_M3_PYTHON`,
  `AI_DEV_EMBEDDINGS_PYTHON`, `AI_DEV_PYTHON_BASE`, `BGE_M3_PYTHON_REVISION` и `BGE_M3_MODEL_DIR`
  называет проверка здоровья, и они не читаются — уберите их и удалите `~/.ai-dev/models/bge-m3`.
  `--dense-python` по-прежнему работает и делает то же, что `--model`. Для Intel Mac нет сборки среды
  ONNX: там dense-поиск выключен, и поиск работает по словам.
- **`AI_DEV_HOME` — это сама папка рантайма.** 2.x клала дерево уровнем ниже, в
  `$AI_DEV_HOME/.ai-dev`; сервер, `setup` и каждая команда `ai-dev` поднимают его при старте, ничего не
  перезаписывая, а `ai-dev doctor` говорит, что перенесено (проверка `runtime_home`). `AI_DEV_HOME`,
  равный вашей домашней папке, сохраняет смысл 2.x. Хуки, поставленные в репозиторий, ищут старое
  место, пока не запустить там `install_agent_hooks` снова.
- **`.codex` больше не читается.** То, что AI Dev хранил там во времена Codex, один раз переезжает в
  runtime home, и это записывается в `state/runtime-home-migration.json`: из `~/.codex` в `~/.ai-dev`,
  а при заданном `AI_DEV_HOME` — из `$AI_DEV_HOME/.codex`, где его читала 2.x для этой установки, в
  `$AI_DEV_HOME`. Остальное в `.codex` принадлежит самому Codex и остаётся на месте, а `npm run demo`
  оттуда ничего не уносит.
- **Всех клиентов обслуживает один демон.** Локальная запись 3.0, `ai-dev mcp`, передаёт клиента одному
  тёплому серверу на установку и окружение, так что индекс и модель загружаются один раз. Запись 2.x
  (`node …/src/server.mjs`), `npm start` и `AI_DEV_DAEMON=0` оставляют по процессу на клиента, как в
  2.x.
- **Хуки агента.** Хуки, поставленные 2.x, работают везде, где `node` есть в `PATH` клиента. Запустите
  `install_agent_hooks` в каждом репозитории снова — регистрации 3.0 стартуют через
  `.ai-dev/hooks/with-node.sh` и находят Node без него; ваши собственные хуки сохраняются. Хуки,
  которые он ставит, приносят два умолчания, которых не было в 2.0.0, — в профилях standard и strict.
  Перед командой установки guard ищет пакет в реестре npm и в OSV и отказывает вредоносному пакету и
  выпуску моложе 24 часов: имена пакетов уходят на api.osv.dev. А если код или манифест зависимостей
  изменился после последнего `run_security_scan`, Stop-хук один раз возвращает агента провести ревью
  безопасности, прежде чем сессия закончится. В `.ai-dev/policy.json`
  `"supply_chain": { "osv": false }` не пускает имена пакетов в OSV, а `"enabled": false` выключает
  проверку (как и `AI_DEV_SUPPLY_CHAIN=off`); `"security_review_on_stop": "remind"` только напоминает,
  `"off"` молчит.
- **Каталог навыков** — 614 навыков, а не 3 228: коннекторы Membrane урезаны с 3 074 до 460, к которым
  обращается разработчик. Навык, который убрало обновление, выпадает из реестра и больше не находится.
- **Поиск.** `AND`, `OR`, `NOT` и `NEAR` заглавными — слова, а не синтаксис запроса. `search_knowledge`
  ищет то, что есть в индексе, — заметки, навыки по записи реестра и карточке, карточки проектов, —
  поэтому справочные файлы навыка (их читает `read_skill`) и заметки в папках вроде `build` или `.next`
  он больше не находит. Панель после обновления один раз устаревает: `ai-dev dashboard` строит её
  заново.
- **Инструменты задачи отвечают сводкой.** `begin_task`, `begin_task_in_worktree`, `checkpoint_task`,
  `verify_task` и `complete_task` возвращают задачу, её критерии и то, что изменилось, а не всю запись
  задачи; команда проверки, которая прошла, приходит без вывода, а длинный вывод упавшей обрезается
  до первых 1 200 и последних 800 символов. Скрипт или клиент, который читал запись из этих ответов,
  берёт её из `get_task`, передаёт `include_details: true` или задаёт `AI_DEV_RESPONSE_MODE=full` в
  окружении клиента — тогда ответы как в 2.x. `search_skills`, `browse_skill_group` и
  `list_skill_groups` отвечают короткими строками (`include_details: true` — все поля), а JSON
  ответа приходит без отступов.
- **Новые файлы** в runtime home: `<файл>.lock` рядом с файлами, в которые пишут несколько процессов,
  `run/` (дескрипторы демона), `logs/daemon.log`, `state/mcp-clients.json`. 2.x их не замечает.

## Клон

`git pull`, затем `cd ai-dev-mcp-server && npm ci && npm run setup`. Флаг `npm ci` не нужен:
`.npmrc` пакета выключает установочные скрипты зависимостей. После этого перезапустите всех
ИИ-клиентов: ещё работающий процесс сервера 2.x зовёт поисковый помощник, который `git pull` удалил.

Само переносится: индекс 2.x и его векторы читаются как есть, состояние задач и хранилище не
трогаются, а реестр навыков следует за обновлённым каталогом. Нужна команда: записи `ai-dev` (их пишет
`npm run setup`), хуки (`install_agent_hooks`) и модель, если вы пользовались Python-бэкендом (`npm run
setup -- --model`).

## Docker

- **Ваши конфиги 2.x продолжают работать.** Они называют лаунчер — `docker/run-mcp.sh`, `run-mcp.ps1`
  или, для Claude на Windows, `ClaudeMcpProxy.exe`, — и тот запускает новый образ до 4.0. Копии
  скриптов 3.0 говорят об этом в stderr: *«ai-dev: this client config runs docker/run-mcp.sh, the 2.x
  launcher, which works until 4.0. Run ./bootstrap.sh (or `ai-dev clients install --docker`) to write
  the 3.0 entry …»*. Установленный `ClaudeMcpProxy.exe` — сборка самой 2.x: он сам отвечает на
  рукопожатие, без instructions сервера и без предупреждения, пока `bootstrap.ps1` не заменит его
  запись.
- **`git pull`, затем bootstrap.** `run-mcp.sh` из 2.x запускал каждую сессию в долгоживущем
  контейнере, поэтому один `docker pull` до ваших сессий не доходит. Запустите `bootstrap.sh`
  (`bootstrap.ps1`) снова: он пишет на их место записи `docker run -i --rm …` и — на macOS и Linux —
  удаляет контейнер, который держала 2.x, `ai-dev-system-runtime-<uid>`, когда переписан каждый конфиг.
  Монтирует он те папки, которые называют ваши записи, и говорит, какие оставил: папку проектов из их
  `AI_DEV_PROJECT_PATH` и папку модели из их `AI_DEV_MODEL_PATH` — кроме папки с моделью Python 2.x без
  `bge-m3-onnx/`: её 3.0 не запускает. Папку записи, заданную не абсолютным путём, он тоже не берёт, а о
  неудавшемся запросе папок говорит.
  Другие папки называют `--project-path` (`-ProjectPath`) и `--model-path` (`-ModelPath`); если записей
  нет, папка проектов — `~/AI-Dev-Projects`, а папка модели не монтируется. Если записи называют разные
  папки проектов, bootstrap останавливается (bootstrap.sh выходит с кодом 64), пока вы не назовёте ту,
  которую оставить.
- **Том сохраняется.** Его первый старт под новым образом занимает около 15 секунд, один раз. Его навыки
  приводятся к seed 3.0 по манифесту seed, а не копированием-если-нет, как в 2.x: то, что несла только
  2.x, удаляется; изменённый вами файл seed сохраняет вашу правку, а обновление лежит рядом как
  `<файл>.seed-new`, пока вы его не перенесёте (`ai-dev doctor` называет каждый); ваши собственные
  навыки не трогаются. Дерево рантайма, оставленное 2.x уровнем глубже (`.ai-dev/.ai-dev`), поднимается.
- **Состояние переезжает на вашу машину** — в `~/.ai-dev/state`, где ведут своё хуки агента, — там, где
  пользователь контейнера, uid 1000, — это вы: macOS, Windows и Linux для первого пользователя. Задачи и
  передачи из тома переезжают туда при первом старте. С другим uid, а также при rootless Docker,
  userns-remap или Podman состояние остаётся в томе, как в 2.x, а сервер не может писать в ваши
  проекты; там выбирайте локальную установку.
- **Проекты монтируются по своему пути** на macOS и Linux, а не в `/workspace`. То, что сервер 2.x
  помнил о проекте, — сессии, инстинкты, решения, — остаётся в состоянии под `/workspace/<имя>` и не
  переносится: с проектами по своему пути сервер начинает их память заново. На Windows они остаются в
  `/workspace`.
- **Что в образе осталось:** `/opt/ai-dev/app` и `/opt/ai-dev/public-seed` (теперь ссылки), команда,
  том `/data`, пользователь и переменные данных. **Чего в нём больше нет:** Python, Playwright и
  Chromium (они в варианте `-browser`, `:latest-browser`), `/opt/ai-dev/search-index` и переменных
  `BGE_M3_ONNX_DIR` и `AI_DEV_DENSE_INSTALLED`. Сборка с `INSTALL_BGE_M3=1` получает сообщение о том, что
  его заменило, — на экране оно остаётся с `--progress=plain`: терминальный вид BuildKit сворачивает
  вывод законченного шага. Шаг из кэша не печатает ничего, так что при следующей сборке того же дерева
  оно видно только с `--no-cache`.
- **`AI_DEV_DOCKER_NETWORK` читают только лаунчеры 2.x.** В записи 3.0 прописан `--network none`:
  проекту, чьим проверкам нужна сеть, ставят там `--network bridge`, а повторный bootstrap возвращает
  `none`.
- **Модель на хосте** монтируется в `/models` (`AI_DEV_MODEL_PATH`, `--model-path`), и переменная
  называет папку над моделями — `~/.ai-dev/models`, где лежит `bge-m3-onnx/`. В 2.0.0 она называла
  папку самой модели, смонтированную в `/models/bge-m3`: такое значение лаунчеры 2.x теперь отклоняют
  (`run-mcp.sh` — с кодом 64) и говорят назвать папку уровнем выше. Папку, где лежит только `bge-m3/`,
  веса удалённого бэкенда, лаунчеры 2.x так и называют. Если её `bge-m3-onnx` — ссылка на другой диск,
  запись 3.0 монтирует саму ссылку. Или положите модель в том
  один раз: `docker run --rm -it --network bridge --mount type=volume,source=ai-dev-system-data,target=/data
  ghcr.io/stonebridgeway/ai-dev-system:latest ai-dev model install`.
- **Bootstrap ничего не ставит.** Он проверяет Docker и говорит, откуда его взять;
  `--install-prerequisites` принимается и получает этот ответ.
- **Теги**: `:latest` двигается только с тегом выпуска новейшей линии и больше не идёт за
  2.x; `:edge` идёт за `main`; `:2` — линия 2.x: перед тегом 3.0 в него копируется `:latest` 2.x, а
  потом его двигает только тег `v2.*`.

## Windows

- **Клон 2.x** прописывал клиентам `AI_DEV_PYTHON=python3`, на что Python для Windows не отзывается.
  `npm run setup` (или `npm run clients:install`) пишет запись 3.0: `ai-dev`, Node по полному пути, без
  `AI_DEV_PYTHON`.
- **`bootstrap.ps1`** переписывает Claude Desktop — он запускал `ClaudeMcpProxy.exe` — и остальных
  клиентов на `docker run … /workspace` и обновляет `C:\ProgramData\AI-Dev-System\run-mcp.ps1`, если он
  там есть. Он ничего не компилирует и больше не ставит Docker Desktop и Node: ему нужны оба (Node
  22.12+), и он говорит, как их поставить.
- **В Docker на Windows** папка состояния общая, но общий в ней только журнал использования: сервер
  видит проект как `/workspace/<имя>`, хуки — как `C:\…\<имя>`.
- **Установщик Windows** появился в 3.0, у него своё устройство: переносить из 2.x ему нечего. Он
  может стоять рядом с клоном или Docker; у каждого клиента остаётся запись `ai-dev`, которую написала
  последняя из установок.

## Что остаётся до 4.0 и что оно говорит

| 2.x | 3.0 | До 4.0 |
| --- | --- | --- |
| `docker/run-mcp.sh`, `run-mcp.ps1` в конфиге клиента | записи `docker run` (`bootstrap.sh`, `bootstrap.ps1`) | запускают образ; говорят в stderr, что они — лаунчер 2.x |
| `ClaudeMcpProxy.exe` для Claude на Windows | запись `docker run` | работает как установлен; больше не компилируется |
| имя сервера `ai-dev-system` | `ai-dev` | работает; `clients list` помечает его `(2.x)` |
| `node ai-dev-mcp-server/scripts/ai-dev.mjs` | `ai-dev` (`bin/ai-dev.mjs`) | выполняет все команды; говорит об этом в stderr |
| `scripts/install-local-mcp-clients.mjs` | `ai-dev clients install` | пишет четырёх клиентов, которых писала 2.x; говорит об этом |
| `scripts/start-local.ps1` | `ai-dev mcp` | запускает его; говорит об этом |
| `scripts/backup-ai-dev-system.ps1`, `restore-ai-dev-system.ps1`, `restore-runtime.ps1`, `run-acceptance.ps1` | `ai-dev backup`, `ai-dev restore`, `npm ci` + `ai-dev setup --frontend-qa`, `npm run check` | запускают их; говорят об этом |
| `--dense-python`, `AI_DEV_DENSE_BACKEND=python` | `--model` | модель ONNX, с пометкой |
| `INSTALL_BGE_M3=1` (сборка образа) | модель в томе или в `/models` | говорит, что его заменило (на экране — с `--progress=plain`; при следующей сборке того же дерева — только с `--no-cache`) |

Удалено сразу, как внутреннее или никогда не выпускавшееся: `scripts/install-docker-mcp-clients.mjs`
(его запускали только bootstrap и CI), `npm run test:search-helper`, `search-index/search_cli.py` и
`/opt/ai-dev/search-index` образа, `embeddings/`, а также формула Homebrew и пакет AUR (`packaging/`),
которые не публиковались.

## Как вернуться

- **Клон.** В `ai-dev-mcp-server`, перед переходом на 2.x: `npm run ai-dev -- daemon stop` и `npm run
  ai-dev -- clients remove` — она убирает из каждого клиента и `ai-dev`, и запись 2.x `ai-dev-system`;
  файл, который с тех пор больше ничто не меняло, получает то, что в нём было, без обеих записей. Затем
  `git checkout <коммит 2.x>` и `npm ci --ignore-scripts`. `npm run setup` 2.x клиентов не подключал:
  подключите их снова командой 2.x `npm run clients:install` — она пишет Cursor, Gemini, VS Code и
  Claude Code — или восстановите файл каждого клиента из лежащего рядом `<файл>.backup-<время>`,
  сделанного до обновления. 2.x читает индекс, записанный 3.0; для `AI_DEV_HOME`, который 3.0 подняла, дайте 2.x
  `AI_DEV_STATE_ROOT=$AI_DEV_HOME/state` и `AI_DEV_SEARCH_INDEX_DIR=$AI_DEV_HOME/cache/search-index`.
- **Docker.** `sh ./bootstrap.sh --image ghcr.io/stonebridgeway/ai-dev-system:2` оставляет папки, которые
  монтируют записи 3.0, и пишет записи, которые запускают образ 2.x с монтированиями 3.0: он видит папку состояния и задачи, переехавшие туда.
  Запущенный собственными лаунчерами 2.x (`AI_DEV_IMAGE=ghcr.io/stonebridgeway/ai-dev-system:2`), он
  держит состояние в томе и этих задач не видит — [Тест обновления](UPGRADE-TEST.md) говорит, как
  скопировать их обратно. В обоих случаях копирование-если-нет 2.x возвращает навыки, которые убрала
  3.0, а следующий старт 3.0 снова их удаляет. `:2` появится с выходом 3.0 — это `:latest` 2.x,
  скопированный в него перед тегом 3.0; до тех пор образ 2.x — сам
  `ghcr.io/stonebridgeway/ai-dev-system:latest`, он же установщик bootstrap по умолчанию, поэтому
  `AI_DEV_INSTALLER_IMAGE` называет собранный вами образ 3.0, которым bootstrap пишет записи:
  `AI_DEV_INSTALLER_IMAGE=ai-dev-system:local sh ./bootstrap.sh --image
  ghcr.io/stonebridgeway/ai-dev-system:latest`. Ответ Docker «pull access denied for ai-dev-system …»
  тут ожидаем: bootstrap пробует скачать и установщик, а затем продолжает с образом, собранным здесь.
- **npx.** `npx ai-dev-system@<версия> setup` ставит эту версию и переводит на неё
  записи; 3.0.0 — первая версия в npm.
- **Установщик Windows.** Удалите его; обновление не ставит более старую версию.
