# Контекст для переноса в новый чат

Один абзац, который можно вставить в пустой чат, и всё остальное как справка. Состояние на
заход по замеру с машины пользователя после мержа в stonebridgeway (Д-30 … Д-36).

---

## Текст для вставки

```
Работаю над https://github.com/BreezeAreaSay/ai-dev-system — это форк
stonebridgeway/ai-dev-system, MCP-сервер ai-dev-mcp-server (Node ESM, .mjs). Задача: перенести
хорошие идеи из https://github.com/affaan-m/ECC, потом влить эту MCP в Argentum Workspace.

Весь разбор, план и история лежат в репозитории: docs/ecc-upgrades/. Начни с PLAN.md (43
кандидата по этапам), DEBTS.md (36 записей долгов со статусами и замерами) и PROMPTS.md
(промпты по сессиям плюс доска состояния). CODE-MAP.md говорит, где что лежит после выноса
кода из главного модуля.

Сделано: этапы 0, 1, 2 целиком; в этапе 3 — восемнадцать позиций из двадцати четырёх, включая
очередь из PROMPT-CLOSE-GAPS.md (шестнадцать пунктов: бюджет на матч правил policy,
зарезервированный слот роутинга для импортированных скиллов, сканеры безопасности,
prune_state, состояния worktree, scan_agent_config, граф импортов, дистилляция правил и восемь
долгов, закрытых кодом), и заход по девяти долгам Д-20 … Д-28 — все девять закрыты кодом с
замерами. Не начаты позиции плана 3.11 (адаптеры Codex/OpenCode), 3.14 (маршрутизация модели и
бюджет токенов), 3.21 (монитор стоимости и зацикливания), пак правил arkts из 3.19 и весь
этап 4 (подготовка к Argentum).

После мержа форка в stonebridgeway/main (PR #37) прошёл заход по замеру с рабочей машины:
`npm run setup` пересобирает устаревшее, а не только отсутствующее; `--dense` после скачивания
весов эмбеддит индекс, иначе плотный поиск видел триста документов из шестисот восьмидесяти
двух; интерпретатор venv резолвится по платформе; свежесть бенчмарка роутинга считается против
файла, который реально читается; падение питоновского помощника сообщается исключением, а не
словом Traceback; из `change-hygiene.mjs` убран сырой NUL, из-за которого модуль не находился
грепом.

Долги: 36 записей, 29 закрыто, 2 закрыты частично (Д-2, Д-18), 5 открыто. Кодом чинятся два —
Д-29 (специалиста не получает ни одна английская задача: ранний выход `pickTaskSpecialist`
смотрит на понятия, а таблица понятий опознаёт только русские формулировки) и Д-35 (на Windows
падает 23–41 тест в каждом из десяти прогонов; нужен текст ассертов, чинить по пересказу
нельзя). Д-5 и Д-11 кодом не закрываются, Д-4 — процессная договорённость.

Правила работы, которых держались всю дорогу:
- всё вливается в main; недочёты не чинятся по ходу, а собираются в DEBTS.md со замером, и
  правятся одним заходом в конце;
- каждая сессия заканчивается десятью прогонами npm run check подряд и строкой «N падений из
  10»; один зелёный прогон доказательством не считается (этот критерий уже ловил два падения
  из десяти и один из десяти);
- новые инструменты только через реестр расширений (src/extensions/*, фабрика createXxxTools,
  host), чистая логика в src/core со своим тестом, модуль не длиннее 800 строк, расширения
  никогда не импортируют mcp-stdio.mjs;
- главный модуль 4 819 строк при потолке 5 076 (SYSTEM_LINE_CEILING в src/core/system-health.mjs),
  инструментов 133;
- в тестах фальшивые секреты собираются конкатенацией — литерал ломает scripts/security-check.mjs;
- хуки в ai-dev-mcp-server/hooks/* копируются в чужие репозитории и не могут импортировать код
  сервера, поэтому общие куски там дублируются осознанно.

Как шла работа: я отправлял сессии по промптам из docs/ecc-upgrades, а ты проверял результат
адверсарными пробниками (не по отчёту), вливал ветку в main и записывал найденное в DEBTS.md.
Продолжаем так же.
```
