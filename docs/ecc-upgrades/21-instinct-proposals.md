# 21. Кандидаты в инстинкты из наблюдений сессии

Пункт [3.5 плана](PLAN.md), позиция C-9 в [gap-анализе](ECC-GAP-ANALYSIS.md).

## Идея из ECC

Наблюдатель continuous-learning-v2: `skills/continuous-learning-v2/hooks/observe.sh` пишет
JSONL со `tool_start`/`tool_complete`, `agents/observer-loop.sh` каждые пять минут будит
`agents/observer.md`, который ищет в накопленном четыре вещи — поправки пользователя,
пару «ошибка → решение», повторяющиеся workflow и предпочтения по инструментам — и считает
для каждой уверенность.

Фоновых процессов сервер не запускает, поэтому цикл разворачивается наизнанку: хук пишет
журнал, а разбор происходит по запросу, инструментом.

## Где проходит граница

Хук копируется в чужие репозитории и не обновляется вместе с сервером, поэтому он остаётся
регистратором: пишет, что видел, и не решает, что это значит. Все шаблоны живут на стороне
сервера, где их можно править и тестировать.

Журнал — это список событий трёх видов:

```json
{ "k": "user",  "t": "Нет, не правь сгенерированный клиент руками", "i": 12 }
{ "k": "tool",  "n": "Bash", "c": "npm test", "i": 13 }
{ "k": "error", "n": "Bash", "c": "node build.mjs", "t": "Error: Cannot find module …", "i": 14 }
```

Не больше шестисот событий (вытесняются самые старые), текст обрезается на трёхстах символах,
команда на двухстах. Ошибка приходит в транскрипте внутри *пользовательского* хода, который
следует за вызовом, поэтому она сопоставляется со своим вызовом по `tool_use_id`, а ход с
результатом инструмента не считается репликой пользователя.

Журнал переписывается целиком при каждом захвате: транскрипт дописывается только в конец и
читается с начала, так что свежий файл — всегда полный.

## Пять шаблонов

| Вид | Когда | Во что превращается |
| --- | --- | --- |
| `correction` | Реплика пользователя с признаком поправки («нет», «не надо», «I said», «instead») — но только после того, как агент что-то сделал | Триггер из условия в самой фразе, действие — сама фраза |
| `stated_rule` | «всегда», «никогда», «впредь», «prefer», «use X instead of Y» | То же разбиение на условие и поведение |
| `resolved_error` | Одна подпись ошибки встретилась дважды, и после последнего падения тот же инструмент отработал с другой командой, которая сама ни разу не падала | «Когда X падает с …, запусти Y» |
| `repeated_command` | Одна и та же команда трижды за сессию | «Когда <назначение>, запусти X» |
| `repeated_chain` | Одна и та же пара команд подряд дважды | «Когда <назначение>, запусти X, затем Y» |

Подпись ошибки — это её первая строка, в которой пути, числа и значения в кавычках заменены
плейсхолдерами: два падения одного модуля с разными путями должны считаться одним.

Назначение команды берётся из небольшой таблицы: `test`/`pytest`/`cargo test` → «прогоняются
тесты» с доменом `testing`, `lint`/`ruff`/`clippy` → `code-style`, `git …` → `git` и так далее.

## Чего инструмент не делает

Он не сочиняет формулировку. Действие кандидата — это фраза пользователя или команда, которую
он видел, а не пересказ: отличить верное обобщение от выдуманного здесь нечем, а
правдоподобный инстинкт, которого никто не говорил, хуже отсутствующего. Та половина работы,
которую в ECC делает модель, здесь остаётся агенту: он читает кандидатов, подтверждает
подходящих и переписывает формулировку через `record_instinct`, если она кривая.

Кандидат — не поведение. Он хранится со статусом `proposed`, не показывается в
`list_instincts` без явного `status: "proposed"`, не попадает в context pack ни при какой
уверенности (сама уверенность ограничена 0.5) и становится инстинктом только через
`update_instinct(action: "confirm")`.

Повторный прогон по тому же журналу ничего не удваивает: кандидат, похожий на уже записанный
инстинкт (по той же мере, по которой `record` объединяет похожие), уходит в `skipped` с
указанием, на что он похож. Иначе один журнал, прочитанный трижды, поднял бы уверенность
инстинкта до потолка на ровном месте.
