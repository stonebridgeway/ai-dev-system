# 18. Fact forcing: первая правка файла и первая разрушительная команда

Пункт [3.18 плана](PLAN.md), позиция C-6 в [gap-анализе](ECC-GAP-ANALYSIS.md).

## Идея из ECC

`scripts/hooks/gateguard-fact-force.js` отклоняет **первый** Write/Edit каждого файла за сессию,
требуя четыре факта — импортёры, затронутый API, схема данных, цитата инструкции, — и **первую**
разрушительную Bash-команду, требуя строку отката. Состояние лежит в
`~/.gateguard/state-<session>.json`, записи живут 30 минут, их не больше пятисот, после трёх
отказов гейт затухает, `GATEGUARD_EXEMPT_GLOBS` выводит пути из-под правила, а невозможность
записать состояние открывает гейт, а не закрывает работу.

Механику мы взяли целиком. Не взяли непроверяемое требование: отказ, на который агент отвечает
повторным вызовом, ничему не учит. Факты проверяются там, где их видно, — в транскрипте, который
харнесс и так пишет.

## Что появилось в коде

| Файл | Роль |
| --- | --- |
| `ai-dev-mcp-server/hooks/fact-force.mjs` | Весь гейт: настройки, глоб-матчер, чтение транскрипта, разбор блока фактов, таблица разрушительных команд, состояние сессии, решение |
| `ai-dev-mcp-server/hooks/guard.mjs` | Вызов гейта после жёстких правил; относительные пути правок |
| `ai-dev-mcp-server/src/core/agent-hooks.mjs` | `fact-force.mjs` в `HOOK_FILES`, блок `fact_force` в `defaultPolicy` |

Тесты: `src/core/agent-hooks.test.mjs` — четыре на чистую логику (настройки и переменные
окружения, глобы и разбор блока, таблица решений с затуханием, срок и предел записей состояния)
и один сквозной, который ставит строгий профиль, пишет транскрипт и запускает настоящий
`guard.mjs`: отказ, ответ фактами, повтор, новая сессия, исключённый путь, стандартный профиль,
команда без отката, жёсткое правило впереди гейта, отсутствие транскрипта.

## Как это работает

PreToolUse срабатывает, когда ход ассистента с вызовом инструмента уже записан в транскрипт.
Значит, факты и правку можно отправить одним ходом: отказ приводит блок дословно, агент пишет
его и повторяет правку, повтор проходит.

```text
FACTS src/router.mjs
importers: src/app.mjs и src/server.mjs
api: добавляет экспорт `resolve`, ничего не удаляет
data: читает таблицу маршрутов в config/routes.json
instruction: "научи роутер разбирать вложенные пути"
```

Ключ засчитывается, если после двоеточия есть хотя бы три символа. Блок читается и в виде
списка Markdown (`- importers: …`), и с жирным заголовком (`**FACTS** \`путь\``); путь
сверяется целиком или по имени файла. Пустой ключ не берёт ответ со следующей строки:
горизонтальный пробел в регулярных выражениях не включает перевод строки — это то место, где
`\s*` был бы ошибкой.

Для команд требование одно:

```text
ROLLBACK: восстановить сборкой npm run build
```

Разрушительными считаются одиннадцать групп: удаление и перемещение файлов, `sed -i`,
переписывание истории git (`--amend`, `rebase`, `revert`, `reset`), `git push`, смена
зависимостей, миграции, запись в БД, инфраструктура (terraform, kubectl, helm, docker),
права и управление сервисами. Необратимое (`rm -rf`, `git reset --hard`, `git push --force`)
до гейта не доходит: жёсткие правила `guard.mjs` отклоняют его раньше и по своей причине.

## Состояние и границы

`~/.ai-dev/state/guard/<session>.json`: когда какой файл был обоснован, когда прошла первая
команда, сколько отказов выдано. Записи старше `expiry_minutes` (30) считаются несуществующими —
файл, к которому агент вернулся через час, обосновывается заново. Записей не больше
`max_entries` (500), лишние вытесняются самыми старыми. После `max_denials` (3) отказов за
сессию гейт перестаёт отказывать и только дописывает строку в контекст: спор с гейтом дороже
самого гейта.

Гейт молчит, когда не может видеть:

- нет транскрипта (Cursor присылает id разговора, а не путь) — правка проходит, файл
  отмечается как виденный;
- состояние не читается или не пишется (домашний каталог только для чтения, песочница) —
  проходит всё;
- путь подходит под `exempt_globs` — по умолчанию `**/*.md`, `**/*.txt`, `**/*.lock`,
  `**/*.snap`, `.ai-dev/**`, `.claude/**`, `.cursor/**`.

Включается в `.ai-dev/policy.json`, в строгом профиле включён по умолчанию. Переменные
`AI_DEV_FACT_FORCE=0|1` и `AI_DEV_FACT_FORCE_EXEMPT=glob,glob` перекрывают политику на один
запуск. Таблица значений по умолчанию живёт в `FACT_FORCE_DEFAULTS`, а копия, которую пишет
установщик, — в `defaultPolicy`; тест сверяет их между собой, чтобы они не разошлись.

## Чего гейт не делает

Он не судит содержание фактов. Проверяется, что четыре утверждения названы и не пусты, а не
что они верны: отличить верный список импортёров от выдуманного хук не может, а притворяться,
что может, — хуже, чем не проверять. Ценность здесь в остановке перед первой правкой файла, а
не в валидации текста.
